# Combined Foundation Model

This project packages a research-oriented foundation model blueprint that combines:

- Non-autoregressive (NAR) generation
- Extended reasoning layers
- Natively multimodal mixture-of-experts routing
- Autoregressive MoE generation
- RLCD-based preference alignment
- RL with verification
- GRPO / RLVR training
- RLHF fine-tuning

It is designed as a runnable prototype and demonstration stack for experimentation, not as a full trillion-parameter production training run.

## Project layout

- `src/combined_foundation/config.py` – architecture and training configuration
- `src/combined_foundation/architecture.py` – model blocks and routing logic
- `src/combined_foundation/training.py` – RL training recipes
- `src/combined_foundation/nemo_integration.py` – optional NeMo compatibility adapter for the stack
- `src/combined_foundation/cli.py` – terminal interface for demo, verification, and training
- `main.py` – simple entry point for local execution

## Folder meaning

- `combined_foundation/` – the custom project you are building
- `src/combined_foundation/` – the actual Python package for architecture, config, training, and NeMo glue
- `build/` – intermediate files generated by PyInstaller during EXE packaging
- `dist/` – the final executable created from the CLI
- `transformers/`, `trl/`, `peft/`, `accelerate/` – upstream Hugging Face repos used as reference stacks and tooling foundations

## NeMo integration

This project includes a lightweight NeMo adapter so the architecture can be aligned with NVIDIA NeMo workflows when the framework is installed. The adapter is intentionally optional so the project still runs in a lightweight local environment without a full NeMo installation.

## Quick start

```bash
cd combined_foundation
python main.py demo
python main.py verify
python main.py train --steps 6
```

## Build Windows EXE

```bash
cd combined_foundation
py -m pip install -r requirements.txt
py -m pip install pyinstaller
py -m PyInstaller --onefile main.py --name combined_foundation_model
```

The built executable appears in the `dist` folder.

## Notes

This project intentionally uses a compact, synthetic implementation so it can run on a laptop or CI environment while still capturing the architecture and training recipe described in the prompt.
